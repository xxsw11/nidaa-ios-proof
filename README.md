# نداء — إثبات iPhone التقني 0.1

28 سبتمبر 2026. **مصدر أصلي مُجهّز؛ لا بناء iOS أو وصول إلى جهاز مثبت بعد.** أُجيزت هذه المرحلة صراحةً. نُفذ ما تسمح به بيئة Windows، وظلت v06 وأرشيفاتها دون تعديل. لا Android ولا نشر ولا تنبيه فعلي.

ابدأ بـ[حالة الإثبات](IOS_PROOF_STATUS.md)، ثم [إعداد Mac وiPhone](Docs/MAC_IPHONE_SETUP.md). افتح `NidaaProof.xcodeproj` على Mac، واختر **NidaaProof-Local**. هو مشروع جاهز للفحص والبناء، وليس IPA موقعة أو تطبيقًا بُني هنا.

| المسار | المحتوى |
|---|---|
| App/ | شاشة SwiftUI رقيقة وخدمات النظام ومنسق الحالة |
| ProofCore/ | نموذج الأدلة ونافذة الاختبار، وحزمة Swift محلية مع 10 اختبارات XCTest غير مشغلة بعد |
| Config/ | إعداد توقيع فارغ عمدًا، وentitlement APNs لمساره المنفصل فقط |
| Scripts/ | فحص Mac وبناء دون تثبيت، وتحضير حمولة APNs دون شبكة |
| QA/ | نتائج Windows، اختبارات التحضير، ومصفوفة الجهاز الفارغة من النتائج المفترضة |
| Docs/ | الإعداد وAPNs والمعمارية وبروتوكول الجهاز ومصادر Apple والمسودة الحرجة |
| NEXT_REVIEW.md | الخطوة التالية الدقيقة والمتطلبات ونقطة التوقف |

التطبيق يقرأ إذن الإشعارات من النظام ويطلبه بفعل المستخدم، ويستخدم LocalAuthentication مع حيوية أو رمز الجهاز، ويجدول إشعارًا محليًا عاديًا واحدًا بعد تحقق جديد. مسار APNs يحتاج توقيعًا مناسبًا وتسجيل جهاز وبيئة إرسال مصرحًا بها؛ لا مزود أو إقرار خادمي متصل. كل هذه وظائف مكتوبة تحتاج البناء والفحص على Apple.

النطاق أصغر من التطبيق الكامل: لم تُنقل دائرة جهات الاتصال أو التصعيد الخادمي أو محرر ألوان v06 إلى تطبيق إنتاجي. الهوية صفراء/سوداء في شاشة الإثبات، وتصميم المنتج الكامل وتخصيصه محفوظان في v06.

لا تبدأ اختبارًا يُصدر إشعارًا أو صوتًا على هاتف فعلي قبل تأكيد المستخدم للجهاز والوقت. عند التأكيد تسجل النافذة داخل الشاشة ويجوز تكرار الحالات ضمن نطاقها دون سؤال لكل حالة. الإذن ببناء المصدر لا يغطي إشعارات لأجهزة أشخاص آخرين.
