# بروتوكول اختبار iPhone الفعلي

النتائج الحالية في [مصفوفة الجهاز](../QA/device-test-matrix.csv): لم يُختبر أي صف على جهاز فعلي. استخدم Passed / Failed / Not tested / Awaiting approval فقط. الحالة لا تُستنتج من التوقع أو من نص الوثائق.

## قبل أول إشعار أو صوت

احصل على تأكيد المستخدم المحدد للجهاز والنافذة والمنطقة الزمنية وأنواع الاختبار. قالب توثيق التأكيد في QA/DEVICE_WINDOW_CONFIRMATION.md؛ غير مملوء وغير معتمد. لا حاجة لسؤال لكل حالة داخل النطاق المؤكد، لكن توسيع الجهاز أو الزمن أو النوع يتطلب تأكيدًا يغطيه. لا ترسل إلى هاتف آخر.

سجل طراز iPhone الفعلي وiOS ونسخة/بصمة البناء وscheme والتوقيع وإذن الإشعار والصوت والقفل والتلخيص وFocus والصامت والمخرج الصوتي والطاقة والشبكة وحالة التطبيق. لا يقرأ الإثبات مفتاح الصامت أو كل إعدادات Focus أو مسار الصوت فعليًا؛ يسجلها المشغّل من الجهاز. لا تضع serial/UDID أو رمز APNs في النسخة القابلة للمشاركة.

## الحالات الأساسية — محلي وAPNs بشكل مستقل

| الحالة | الإجراء داخل النافذة المؤكدة | الدليل المطلوب |
|---|---|---|
| Foreground | أبق التطبيق ظاهرًا أثناء إشعار واحد | ظهور/صوت وما سجله foreground callback، كل منها مستقل |
| Background | جدوِل المحلي أو جهز APNs ثم اخرج للرئيسية | وقت الملاحظة اليدوية، العرض والصوت، والرصد اللاحق |
| Screen locked | اقفل الشاشة قبل الإشعار | العرض على القفل ومحتوى المعاينة والصوت، دون افتراض callback |
| Silent mode | فعّل الصامت وسجل حالته ثم اختبر | هل صدر صوت وأين؟ لا تسم النتيجة تجاوزًا للصامت دون دليل |
| Focus / DND | سجل اسم وضع الاختبار واستثناءاته، ثم فعّله | العرض والصوت والتأخير؛ لا تعمم على كل إعدادات Focus |
| Bluetooth / AirPods | اربط سماعة الاختبار المصرح بها وسجل مخرج الصوت | ما سُمع من كل مخرج، دون ادعاء القدرة على اختيار كل المخارج |
| Low Power Mode | فعّل الطاقة المنخفضة | العرض والتأخير والصوت وحالة التطبيق الفعلية |
| Network disconnect/restore | افصل الشبكة ثم اختبر المحلي، وأرسل APNs فقط إن كان المرسل متصلًا ومخوّلًا؛ أعد الشبكة داخل المهلة | المحلي لا يثبت نقلًا؛ سجل قبول المزود ثم الوصول/عدم الوصول. أعد حالة منفصلة بعودة بعد TTL |
| User force-quit | جدوِل المحلي قبل السحب من مبدل التطبيقات، وأرسل APNs عاديًا من الاختبار المستقل | هل ظهر الإشعار؟ هل سمع الصوت؟ متى عاد التطبيق؟ لا تتوقع callback وقت الإغلاق |

صفوف Critical Alerts منفصلة بحالة Awaiting approval؛ لا تُشغّلها الآن. بيانات كل صف مستقلة: لا نسخ Passed من local إلى remote أو من Foreground إلى Background.

## تفسير القياس

Passed يعني اجتياز معيار الحالة المتفق عليه وتسجيل دليل فعلي، وليس بالضرورة صدور صوت. مثلًا، منع إجراء بعد إلغاء المصادقة نتيجة صحيحة؛ وغياب الصوت العادي في إعداد معين يُسجل كغياب صوت دون اختلاق تجاوز للصامت. Failed يعني مخالفة معيار محدد أو إخفاقًا قابلًا لإعادة الاختبار، وليس مجرد عدم توفر جهاز. Not tested لعدم التنفيذ؛ Awaiting approval عندما يلزم الإذن الخاص.

اكتب معيار النجاح المقصود قبل تشغيل الصف في acceptance_criterion، ثم observed_result وevidence_path بعده. احتفظ بأي expected behavior خارج خانة الملاحظات الفعلية. سجّل المناطق الزمنية، ولا تسم وقت فتح الإشعار وقت وصوله الأصلي. provider_acceptance يأتي من APNs؛ app_observation من التطبيق؛ server_ack غير مفعّل؛ human_response من زر منفصل.

## اختبارات الحماية والمصادقة المطلوبة كذلك

1. نجاح Face ID/Touch ID المتاح، فشل حيوية، إلغاء المستخدم، بديل رمز الجهاز، عدم إعداد حيوية، عدم إعداد رمز، وقفل الحيوية بعد محاولات النظام المسموحة؛ لا تخمّن رمزًا أو تكرر محاولات خطرة.
2. انتقال للخلفية أثناء المصادقة، وانتهاء نافذة الاختبار خلالها: لا جدولة من نجاح قديم. إلغاء الاختبارات أثناء طلب جدولة جارٍ: إزالة المحلي المعلق.
3. إذن لم يُطلب ثم قبول ثم رفض/سحب من الإعدادات: يعرض الحالة الفعلية؛ الرفض لا يعرض نجاح إرسال.
4. فتح إشعار دون زر استجابة: لا قبول بشري. استجابة صريحة بعد تحقق: حدث محلي فقط. إشعار منتهٍ أو ملغى: لا استجابة جديدة. تكرار الرصد: لا تصفير للوقت الأول.
5. VoiceOver وDynamic Type وRTL والتمرير والشريط السفلي وlandscape: اختبار بصري/لمسي فعلي، لا اعتماد على تحليل المصدر. سجل لقطة جهاز إن سُمح بذلك ولا تشمل رمز APNs.

توجد صفوف هذه الفحوص في QA/additional-device-checks.csv. XCTest يغطي قواعد أدلة نقية فقط؛ لا يثبت API الأصلية.

## الإنهاء

أوقف المرسل البعيد، واضغط إيقاف الاختبارات، وراجع مركز الإشعارات. لا تتجاوز النافذة لانتظار تأخير غير محدود؛ سجل عدم وصول ضمنها. احتفظ بالأدلة محليًا دون أسرار. حدّث IOS_PROOF_STATUS وNEXT_REVIEW بنتائج فعلية، ولا تنتقل للتطبيق الكامل حتى تقييم الفجوة الفنية.
