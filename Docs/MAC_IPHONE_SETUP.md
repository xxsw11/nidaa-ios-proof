# إعداد Mac وiPhone

## ما يلزم توفيره

1. Mac مع Xcode كامل ومكونات iOS التي تدعم إصدار جهاز الاختبار. المصدر يستخدم حدًا أدنى iOS 16 وSwift tools 5.9؛ استخدم Xcode حديثًا ملائمًا للجهاز، وسجل نسخته الفعلية.
2. iPhone يخص المستخدم أو جهاز اختبار مخول له، بكابل أو اقتران تطوير، وإصدار iOS ورمز جهاز. يلزم Face ID أو Touch ID مُعد لاختبار الحيوية؛ عدم توفره حالة يجب اختبارها أيضًا.
3. حساب Apple يُستخدم محليًا في Xcode وقدرات توقيع متاحة. يحتاج APNs فريقًا وApp ID وملف provisioning يدعم Push Notifications؛ لا نفترض وجود عضوية أو نشتريها. لا ترسل كلمة مرور أو مفاتيح في المحادثة.
4. قبل الصوت أو الإشعار: تأكيد محدد لاسم مستعار للجهاز ووقت البداية والنهاية والمنطقة الزمنية، وهل يشمل النطاق المحلي وAPNs والسماعات. حتى ذلك الوقت يجوز الفحص والبناء فقط.

## فتح المصدر وفحص البيئة — بلا صوت

انسخ مجلد الحزمة إلى Mac. من Terminal داخل المجلد:

```bash
bash Scripts/mac_preflight.sh
```

الفحص يقرأ نسخة النظام وXcode وSwift وملفات المشروع والأجهزة وهويات توقيع الشهادات العامة؛ لا يبني أو يثبّت أو يرسل. احتفظ بالمخرجات الحساسة محليًا، ولا تشارك قائمة الأجهزة أو الحسابات خامًا. إذا أشار xcode-select إلى CommandLineTools فقط، اختر Xcode الكامل من إعدادات Locations الخاصة به أو اضبط مساره محليًا. جهّز المكونات الناقصة يدويًا؛ لا تثبيت أو ترخيص جديد ضمن السكربت.

## إعداد المشروع والبناء

1. افتح `NidaaProof.xcodeproj`. المشروع بصيغة property-list XML، بمرجع محلي إلى `ProofCore`؛ لا SwiftPM خارجي أو CocoaPods أو XcodeGen.
2. انسخ `Config/Developer.example.xcconfig` إلى `Config/Developer.xcconfig`، وضع **Bundle ID الذي تختاره وتملكه لهذا الاختبار** و**DEVELOPMENT_TEAM الخاص بحسابك**. القيم فارغة عمدًا. الملف الخاص مستثنى من Git؛ لا يضم أسرارًا أو شهادة.
3. اختر scheme **NidaaProof-Local** وDebug. لا تستخدم APNs قبل إعداده. لا توجد entitlements في Debug/Release؛ الملف الخاص بالدفع يرتبط بـAPNs-Debug فقط.
4. شغّل `bash Scripts/mac_build_local.sh`. ينفذ `swift test --package-path ProofCore` ثم بناء Simulator دون توقيع أو تثبيت أو تشغيل. هذا لم يُنفذ على Windows. أصلح أخطاء البناء الفعلية وسجلها قبل أي ادعاء نجاح.
5. على Xcode، اختر iPhone وSigning & Capabilities والفريق. استخدم بيانات توقيعك المحلية. لا تفعل `-allowProvisioningUpdates` آليًا؛ إذا تطلب Xcode تسجيل جهاز أو تغيير App ID فراجعه مع المستخدم قبل تغيير الحساب الخارجي. ما هو متاح بحساب شخصي يكفي فقط للميزات التي يمنحها ملفه؛ لا تفترض دعمه APNs.
6. عند الاقتران، وافق على Trust وفعّل Developer Mode من iPhone إذا طلب النظام، بحضور المستخدم. هذه تغييرات ينفذها المستخدم على جهازه. المصدر لا يغيرها.
7. Build أولًا. سجل نسخة Xcode وiOS والجهاز ونتيجة البناء والتوقيع. يمكن فتح التطبيق دون إرسال، لكنه ليس إثبات تنبيه حتى تنفيذ الحالات المتفق عليها.

## بعد تأكيد الجهاز والنافذة

اطلب إذن الإشعارات من داخل التطبيق واقرأ حالته الفعلية. جرّب تحقق النظام وحده، ثم أدخل اسم الجهاز المستعار ونهاية النافذة وسجل التأكيد. زر الاختبار المحلي يجري تحققًا جديدًا ثم يطلب إشعارًا واحدًا بعد 15 ثانية، مع 20 ثانية على الأقل متبقية في النافذة عند الفحص. لا إشعار متكرر أو إرسال تلقائي عند التشغيل.

اتبع [بروتوكول الاختبار](DEVICE_TEST_PROTOCOL.md) وأكمل CSV لكل حالة. شغّل حالات الخلفية والقفل من تثبيت الجهاز بعد فصله عن جلسة debugger حتى لا تؤثر في الملاحظة؛ دوّن وجود debugger إن استخدمته. إشعار محلي على Simulator لا يغلق صف iPhone، ولا يغلق صف APNs.

عند الانتهاء اضغط إيقاف الاختبارات، أوقف أي مرسل APNs، وألغِ المعلّق قبل انتهاء النافذة. توقف عن الإرسال مبكرًا لإتاحة رصد تأخر النظام. إزالة إشعار أو إلغاء تسجيل APNs ليست ضمانًا لإيقاف صوت بدأ أو سحب إشعار بعيد قيد النقل.
