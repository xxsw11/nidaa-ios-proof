# تشغيل التجربة المحلية

## على Mac

1. افتح مشروع `NidaaProof.xcodeproj` الموجود، واختر scheme `NidaaProof-Local` ثم iPhone Simulator. يتطلب المشروع iOS 16 فأحدث وXcode يدعم المحاكي المتوفر.
2. للمحاكي فقط، مرر `NIDAA_BUNDLE_ID=com.example.nidaa.simulatorproof` مع تعطيل التوقيع كما يفعل `Scripts/ci_simulator.sh`. هذا معرّف اختبار محاكي غير مسجل، وليس هوية إنتاجية أو حسابًا مخترعًا.
3. شغّل `swift test --package-path ProofCore` ثم `bash Scripts/ci_simulator.sh` لاختبارات الواجهة وبناء Release. السكربت يشغّل محاكيًا، ولا يرسل إشعارات ولا يحتاج أسرارًا.
4. للتجربة اليدوية في Debug Simulator: الإعدادات ← مصادقة محاكية على Simulator. عند كل تحقق اختر النجاح أو الفشل أو الإلغاء. يبقى التنبيه الذي يوضح المحاكاة ظاهرًا. بديلًا يمكن استخدام LocalAuthentication الخاص بالنظام؛ ذلك لا يثبت العتاد الحقيقي.

## رحلة العرض

- الرئيسية ← إنشاء نداء ← اختر أشخاصًا ذوي موافقة سارية ونوع المساعدة ← تحقق جديد ← راجع الاختيار وأكّد صراحةً. إلغاء التحقق أو التأكيد أو الانتقال للخلفية لا ينشئ نداء.
- تفاصيل الصادر ← محاكاة الاستلام لكل مستلم ← افتح الوارد ← سأتولى الاستجابة أو لا أستطيع. فتح الشاشة والإسكات والإخفاء لا يمثل قبولًا أو إنهاءً.
- أنهِ الحالة بتأكيد صريح، أو ألغِ الصادر. إعادة المحاولة تحفظ المعرّف والاستجابات. أدوات الزمن المحلي تتيح إظهار عدم الاستجابة بعد 25 ثانية وانتهاء الصلاحية بعد خمس دقائق دون انتظار فعلي.
- دائرتي ← إضافة/تعديل/حذف، أو غيّر الدعوة وموافقة الاتجاهين. المعلّق والمرفوض والمحظور لا يجيزون إرسالًا أو استقبالًا. الدعوات محلية ولا تُرسل لأحد.
- الإعدادات ← المظهر: داكن/فاتح/النظام، أساسي وأزرار وخلفية، معاينة ثم حفظ/إلغاء/استعادة. النص يُضبط للتباين، والتغيير أثناء نداء نشط يُحفظ ويؤجل تطبيقه حتى انتهاء الحالات النشطة.
- القفل اليدوي في الرئيسية يحمي التفاصيل؛ محاكاة الوارد أثناءه تعرض نصًا عامًا مع إسكات، ثم تتطلب فتح القفل للاستجابة. فتح القفل لا يغني عن تحقق إنشاء جديد.
- الخصوصية والشروط مسودتان أوليتان تعكسان التخزين المحلي، ولا تحددان جهة قانونية أو خدمة غير موجودة.

## البيانات وحدود الاختبار

تفضيلات المظهر، جهات العرض الخيالية، وخيار القفل محفوظة في UserDefaults. النداءات وسجل الأحداث ونتائج التحقق في الذاكرة فقط؛ لا ندعي استمرار نداء بعد إنهاء العملية. حذف جهة يمنع التعاملات اللاحقة وقد يُبقي لقطة اسمها في سجل الجلسة حتى إعادة التشغيل أو إعادة الضبط. لا دفتر عناوين أو ميكروفون أو موقع أو كاميرا أو تحليلات.

وضع XCTest يستخدم مساحة تفضيلات منفصلة `nidaa.ui.tests`. قيم النجاح والفشل والإلغاء المؤتمتة متاحة فقط مع العلم الخاص باختبار الواجهة داخل Debug Simulator. لا تُستعمل للتحقق من حيوية وجه أو بصمة.

كل واجهات إشعار النظام وتسجيل APNs تتوقف عند `ExecutionScope.allowsSystemNotifications = false` حتى في مسار APNs المحفوظ تاريخيًا. قراءة حالة الإذن وطلبه بفعل المستخدم متاحان؛ الطلب المرفوض لا يعاد تلقائيًا. الاختبارات لا تضغط زر طلب الإذن.

## الاختبار السحابي

GitHub Actions على runner عام قياسي `macos-15`: Python، Swift Core، اختبارات واجهة XCTest مع مرفقات صور، ثم بناء Release. الأدلة في artifact لمدة 7 أيام وفق الإعداد؛ حالة التشغيل والرابط يردان في CLOUD_BUILD_STATUS.md. لا خدمات مدفوعة أو backend أو أسرار أو أجهزة أشخاص آخرين.
