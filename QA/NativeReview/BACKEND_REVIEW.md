## Restore procedure and proof boundary

Migration `005_review_restore_barriers.sql` adds an RLS-protected maintenance row, session revocation ledger and per-account projection digest. Client roles cannot read or mutate either new control table; a regression exercises actual SQL role restrictions.

1. Create the historical backup in an isolated environment as before.
2. On the source, run `python -m Integration.service.worker export-ledger --file <private path>`. This atomically quiesces shared API calls and worker processing and exports format 2, including an opaque export ID, source database name, cursor watermark and complete deletion/relationship/session barriers. The source remains quiesced after the file is written.
3. Restore the old dump into a **different database**, inaccessible to application clients. Set the worker's `DATABASE_URL` to that destination and `RESTORE_SOURCE_DATABASE_URL` to the still-quiesced source using private environment configuration. Never paste either credential-bearing URL into messages or artifacts.
4. Run `replay-ledger --file <private path>`. It verifies the live source's quiescence, matching export ID, unchanged watermark and exact ledger contents; rejects legacy/missing metadata, changed/truncated records, stale exports and the same source/destination database; applies barriers; raises cursors; and opens the destination only after commit. Source and destination locks prevent shared domain writes during this verification.
5. Verify the isolated destination. Resume the source explicitly with its original `DATABASE_URL` and `resume-source --file <same private export>`. The test always resumes in `finally` and drops only its generated destination database.

The source health endpoint and shared API return unavailable during quiescence; logout cannot falsely return success during that interval. Provider registration/login alone is not a shared-domain mutation and cannot bypass the domain maintenance gate. Export/restore files remain private temporary data and are excluded from evidence.

Watermark proof: before export, each client can only have observed its account's authoritative monotonically increasing cursor. Therefore it cannot exceed the source-wide maximum captured under the write barrier. While quiesced, no shared domain request/worker can advance that maximum or change barriers. Destination cursors above the exported maximum are newer than every pre-export client cursor. A second replay is also safe and newer. This does **not** certify arbitrary disaster restoration when the source is unavailable, the export is stale or clients have seen later state. Such a deployment needs a durable epoch/reset protocol and independent backup inventory; it is outside this local drill.

The exported barriers cover domain deletion, consent withdrawal/block and session revocation. They are not an independent provider-admin audit stream: a raw Auth-admin ban applied after an old backup requires provider-specific recovery handling. Normal API and worker execution always consult live provider status; arbitrary provider-admin disaster recovery is not proven by this drill.

## Other reviewed boundaries

- User IDs are independent of provider subjects/names. JWT verification, actual verified provider rows, actual live sessions and domain barriers remain mandatory. Recent authentication uses signed AMR, not refresh time or local Face ID.
- Client SQL roles have no direct grant/alert writes; service credentials have only the required provider identity/session columns. New policies do not grant password/token access, table ownership or BYPASSRLS.
- Directional consent, blocks/withdrawal, third-party denial and first-committed response semantics remain enforced in the existing command transaction. No authorization assertion or prior test was removed.
- Receipts and outbox updates remain atomic; immutable payload fingerprints and UUID normalization remain intact. Retry/add commands preserve original deadlines and exclude answered/declined recipients. Terminal alerts never reopen.
- Fake handoff is a database transaction, with crash/restart deduplication; this does not prove external exactly-once notification delivery or APNs reception.
- Thirty-day history and 90-day operation/removal retention remain provisional choices. Revocation/deletion/session ledgers are not automatically expired until a backup inventory establishes when that is safe.
- The global advisory lock, read-time sweeps and bounded snapshots are deliberate local-trial limits. The new cap is not a production scaling claim, and an overflow needs explicit maintenance or a future paging contract rather than silent truncation.

No public service, external email, push notification, purchase, branch merge or physical-device operation occurred in this review scope.
